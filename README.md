# 인생관리공단 (LIFE MANAGEMENT OFFICE)

당신의 인생, 저희가 대신 이해해 드립니다.

## 실행 방법

Node.js 20 이상이 필요합니다.

```bash
npm install
npm run dev
```

브라우저에서 http://localhost:3000 을 엽니다. 환경 변수가 없으면 게스트 모드로 실행되며, 시민 정보는 그 브라우저에만 저장됩니다.

Windows에서도 같은 명령을 씁니다. `npm install`이 만드는 `package-lock.json`은 함께 커밋하세요.

## Supabase 연결 (선택)

1. Supabase 프로젝트를 만듭니다.
2. SQL Editor에서 `supabase/migrations/`의 파일을 번호 순서대로 실행합니다.
3. Authentication 설정에서 Anonymous sign-ins를 켭니다.
4. `.env.example`을 `.env.local`로 복사하고 URL과 anon key를 채운 뒤 개발 서버를 다시 시작합니다.

## 폴더 구조

```text
src/
  app/                  라우트. 화면 조립만 담당
  components/
    character/          캐릭터 렌더러와 파츠 그림
    mascot/             감자 과장님 (expression, pose)
    ui/                 앱 틀, 로고, 로딩·오류 상태
  features/
    plaza/              메인 광장, 오늘의 사건
    register/           시민 등록 5단계
    editor/             캐릭터 편집기, 촬영실
    card/               시민증
  lib/
    character/catalog.ts  파츠 목록, 저장 형식, 검증, 랜덤
    citizen/              저장소(게스트, Supabase)와 useCitizen
    daily/                매일 바뀌는 템플릿과 날짜 계산
supabase/migrations/    스키마와 RLS
```

## 파츠 추가하기

1. `lib/character/catalog.ts`의 목록에 `{ id, label }`을 추가합니다.
2. `components/character/parts/`의 해당 `Record`에 그림을 추가합니다. 빠뜨리면 타입 오류가 납니다.

캐릭터 설정은 `citizens.character`(jsonb)에 파츠 ID와 색상으로 저장합니다. 없어진 ID는 불러올 때 `sanitizeCharacter`가 기본값으로 되돌립니다. 레이어 순서는 `Character.tsx` 상단 주석에 있습니다. 의상은 몸 윤곽으로 잘리므로 한 번만 그려도 네 가지 몸 형태에 모두 맞습니다.

## 디자인 원칙

- 민원 창구: 벽, 카운터, 번호표, 서류 봉투, 도장 같은 주민센터 소재로 화면을 구성합니다.
- 글꼴: 제목은 Jua, 공문 본문은 Gowun Batang, 과장님 말풍선은 Gaegu입니다.
- 말투: 사회에 지친 사람에게 위로가 되지만, 위로하는 티를 내지 않습니다. "괜찮아요", "힘내세요" 대신 공단이 귀찮아서 대충 처리한 결과로 시민의 짐이 줄어듭니다. 무심한 쪽은 언제나 공단이고, 시민을 깎아내리지 않습니다. 삶을 끝내거나 사라지는 농담은 쓰지 않습니다. 자세한 기준은 `src/lib/daily/content.ts` 상단에 있습니다.
- 민원 답변: 짧게 받아넘긴다("아 그러세요", "네, 그렇군요"). 지친 글에는 "안 궁금합니다"를 쓰지 않는다.
- 정직한 화면: 집계되지 않은 숫자나 없는 사용자를 보여 주지 않고, 미완성 시설은 공사 중으로 표시합니다.

## 힘든 내용이 입력될 때

민원 진술에 자살이나 자해를 떠올리게 하는 표현이 있으면 농담 판정을 만들지 않고, 저장도 하지 않은 채 109 상담전화를 안내합니다. 단어 기반 검사(`lib/complaint/generate.ts`)라서 놓칠 수 있고 잘못 걸릴 수도 있으므로, 잘못 걸렸을 때 돌아가는 버튼을 둡니다. 공개 전에 전문가 검토를 받으면 좋습니다.

## 개인정보

이메일 등 인증 정보는 Supabase `auth.users`에만 있고 공개 테이블 `citizens`에는 없습니다. 등급, 칭호, 사건 수는 클라이언트가 직접 수정할 수 없도록 열 단위 권한으로 막았습니다.
